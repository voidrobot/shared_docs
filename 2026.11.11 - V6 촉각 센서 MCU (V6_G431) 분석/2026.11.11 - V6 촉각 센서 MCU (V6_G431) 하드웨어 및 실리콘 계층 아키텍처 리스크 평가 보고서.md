## 1. 개요

본 보고서는 상위 센싱 알고리즘이나 상태 머신 로직을 배제하고, **실리콘 내부 버스 아키텍처, 플래시 메모리 컨트롤러 한계, 인터럽트 우선순위 계층(NVIC), DMA 버스 중재, 하드웨어 타이머/페리페럴 레지스터 구성, 물리 계층 신호 무결성**의 관점에서 시스템의 신뢰성과 실시간성을 저해할 수 있는 하드웨어 및 실리콘 아키텍처 주요 리스크 항목들을 평가한다.

> [!CAUTION]
> 본 보고서는 펌웨어 소스코드와 레지스터 설정, 제조사 공식 사양(ST RM0440 Reference Manual, STM32G431xB/xC/xD Datasheet, ARMv7-M Architecture Reference Manual)에 기반한 정적 분석 결과이므로, 실물 PCB의 외부 회로 환경 및 배선 인덕턴스에 따라 실제 런타임 영향도에 차이나 예외가 존재할 수 있다. 또한 본 분석 결과가 대상 시스템의 모든 잠재적 하드웨어 및 실리콘 리스크를 전수 검출했음을 보장하지 않는다.

## 2. 주요 리스크 분석

본 절에서는 식별된 하드웨어 및 실리콘 아키텍처 리스크 항목들을 시스템 안전성, 실시간 센싱 주기성, 데이터 무결성에 미치는 영향도에 따라 3단계 위험도 체계로 분류하여 평가한다.

### 위험도(Risk Level) 분류 체계 및 판정 기준

| 위험도 등급 | 심각도 정의 |
| :--- | :--- |
| **상** | 즉각적인 시스템 동결(Lock-up), 버스 스톨(Bus Stall), 장시간 센싱/통신 공백 또는 영구 인터럽트 기아를 초래할 수 있는 치명적 설계 결함 |
| **중** | 고속 통신 프레임 손실(ORE), 센싱 주기 위상 지터 누적, 하드웨어 선점 불가 등 시스템 신뢰성과 실시간 성능을 유의미하게 저하시키는 리스크 |
| **하** | 잠재적 예외 발생 가능성 또는 버스 대역폭 비효율을 내포하나, 정상 운용 조건에서 즉각적인 제어 중단을 유발하지 않는 구조적 한계 |

### 1. Single-Bank Flash 구조로 인한 파라미터 저장 시 CPU 버스 하드웨어 스톨
- **위치**: `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/env_flash.c:L16-L17, L76-L117`, `Src/main.c`
- **위험도**: **상**
- **구조적 원인**:
  STM32G431CBU6 MCU는 128 KB 플래시 메모리를 탑재한 **싱글 뱅크(Single-Bank) 구조**이다. 런타임에 캘리브레이션 파라미터를 플래시(0x08003800, Page 7)에 저장하기 위해 `HAL_FLASHEx_Erase()` 및 `HAL_FLASH_Program()`을 실행한다[^1].
- **공식 기술 규격 검증**:
  ST RM0440 (STM32G4 Reference Manual) 플래시 메모리 컨트롤러 명세에 따르면, 듀얼 뱅크(Dual-Bank)가 지원되지 않는 싱글 뱅크 MCU에서는 플래시 페이지 소거(Page Erase) 및 단어 프로그래밍(Word Programming)이 진행되는 동안 Flash Memory Controller(FMC)가 코어의 코드 페치(Instruction Fetch) 버스 트랜잭션을 하드웨어적으로 정지(Bus Stall)시킨다[^1].
  - STM32G4 페이지 소거 시간($t_{ERASE}$): 일반 **22.0 ms**, 최대 **40.0 ms**
  - 플래시 프로그래밍 시간: 더블 워드(64비트)당 약 **82 µs**
- **잠재적 영향**:
  소프트웨어가 인터럽트를 비활성화하지 않더라도 실리콘 버스 컨트롤러가 CPU 전체를 20~40 ms 동안 물리적으로 동결시킨다. 4 Mbps 반이중 UART 버스 및 200 Hz(5 ms) I2C 센서 샘플링 파이프라인이 4~8주기 동안 완전히 중단되며, 해당 시간 동안 메인 모션 제어기가 발송하는 모든 다이나믹셀 폴링 패킷에 응답하지 못해 타임아웃 통신 에러를 유발한다.

### 2. 20개 전 페리페럴/DMA 플랫 NVIC 인터럽트 우선순위(`0, 0`) 설정으로 인한 하드웨어 선점 불가
- **위치**: `02_V6S_Sensor_FWCube2.1.0/Src/stm32g4xx_hal_msp.c:L268-L271, L348-L351, L428-L431, L685, L757`, `Src/main.c:L714-L745`
- **위험도**: **상**
- **구조적 원인**:
  ```c
  HAL_NVIC_SetPriority(USART1_IRQn, 0, 0);
  HAL_NVIC_SetPriority(USART2_IRQn, 0, 0);
  HAL_NVIC_SetPriority(I2C1_EV_IRQn, 0, 0);
  HAL_NVIC_SetPriority(I2C1_ER_IRQn, 0, 0);
  HAL_NVIC_SetPriority(I2C2_EV_IRQn, 0, 0);
  HAL_NVIC_SetPriority(I2C2_ER_IRQn, 0, 0);
  HAL_NVIC_SetPriority(I2C3_EV_IRQn, 0, 0);
  HAL_NVIC_SetPriority(I2C3_ER_IRQn, 0, 0);
  HAL_NVIC_SetPriority(DMA1_Channel1_IRQn, 0, 0);
  // ... 페리페럴 9개 및 DMA 채널 11개 총 20개 인터럽트 전원 (0, 0) 설정
  ```
- **공식 기술 규격 검증**:
  ARMv7-M 아키텍처 및 Cortex-M4 NVIC 규격에 따르면, 중첩 인터럽트(Nested Interrupts)에 의한 선점(Preemption)은 신규 진입 인터럽트의 선점 우선순위(Preempt Priority) 수치가 현재 실행 중인 ISR의 선점 우선순위 수치보다 엄격히 작을 때(`New < Current`)에만 허용된다[^2]. 동일한 선점 우선순위를 갖는 인터럽트 간에는 하드웨어 선점이 일절 발생하지 않으며, 먼저 진입한 ISR이 복귀할 때까지 대기(Pending)한다.
- **잠재적 영향**:
  모든 페리페럴이 `0, 0`으로 묶여 있으므로, USART1 인터럽트가 실행되는 동안 I2C1/2/3의 DMA 전송 완료 또는 에러 인터럽트가 선점하지 못한다. 특히 USART1 콜백 내부의 420 µs 비지웨이트 루프 실행 중 I2C 하드웨어 이벤트 처리가 지연되어 센싱 타이밍 지터와 DMA 버퍼 덮어쓰기 위험이 증폭된다.

### 3. 4 Mbps 고속 반이중 UART 하드웨어 FIFO 인위적 비활성화 (`HAL_UARTEx_DisableFifoMode`)
- **위치**: `02_V6S_Sensor_FWCube2.1.0/Src/main.c:L643` (`MX_USART1_UART_Init`)
- **위험도**: **중**
- **구조적 원인**:
  ```c
  if (HAL_UARTEx_DisableFifoMode(&huart1) != HAL_OK)
  {
    Error_Handler();
  }
  ```
- **공식 기술 규격 검증**:
  ST RM0440 USART 규격에 따르면, STM32G4에 내장된 USART1은 8바이트 하드웨어 FIFO(TXFIFO 및 RXFIFO)를 제공한다[^3]. 4,000,000 bps(4 Mbps) 전송 속도에서 1바이트 전송 시간은 $10 \text{ bits} / 4,000,000 = \mathbf{2.5 \, \mu s}$에 불과하다. FIFO가 비활성화되면 수신 데이터 레지스터(`RDR`)는 단 1바이트의 완충 여유만을 가진다.
- **잠재적 영향**:
  FIFO가 꺼진 상태에서 메인 MCU나 다른 센서/모터가 4 Mbps로 패킷을 연속 송출할 때, DMA 버스 중재 지연이나 다른 인터럽트 실행으로 인해 수신 지연이 $2.5 \, \mu s$를 초과하면 즉각 하드웨어 수신 오버런 에러(`ORE`)가 발생한다. 이는 통신 인터페이스의 프레임 손실을 유발한다.

### 4. I2C 하드웨어 클록 스트레칭 활성화(`I2C_NOSTRETCH_DISABLE`) 및 버스 결착 취약성
- **위치**: `02_V6S_Sensor_FWCube2.1.0/Src/main.c:L406, L454, L502` (`MX_I2C1_Init`, `MX_I2C2_Init`, `MX_I2C3_Init`)
- **위험도**: **중**
- **구조적 원인**:
  ```c
  hi2c1.Init.NoStretchMode = I2C_NOSTRETCH_DISABLE;
  hi2c2.Init.NoStretchMode = I2C_NOSTRETCH_DISABLE;
  hi2c3.Init.NoStretchMode = I2C_NOSTRETCH_DISABLE;
  ```
- **공식 기술 규격 검증**:
  NXP I2C 버스 규격(UM10204) 및 ST RM0440 I2C 사양에 따르면, 클록 스트레칭(Clock Stretching)이 활성화된 상태에서 슬레이브 디바이스(LPS27HH)가 내부 변환 지연이나 전원 노이즈로 인해 SCL 라인을 LOW로 결착(Stuck-at-Low)시키면, 마스터(MCU)의 하드웨어 상태 머신은 슬레이브가 SCL을 해제할 때까지 무기한 대기 상태에 빠진다[^4].
- **잠재적 영향**:
  센서 배선 접촉 불량이나 ESD 노이즈 유입으로 센서가 SCL을 LOW로 붙잡을 경우, 하드웨어 I2C 컨트롤러가 영구 블로킹된다. 비록 소프트웨어 복구 루틴(`i2c_bus_recover`)이 존재하지만, 타임아웃 감지 전까지 해당 채널 I2C 통신이 마비된다.

### 5. 11개 전 페리페럴 DMA 채널의 동일 저우선순위(`DMA_PRIORITY_LOW`) 설정
- **위치**: `02_V6S_Sensor_FWCube2.1.0/Src/stm32g4xx_hal_msp.c:L242, L259, L322, L339, L402, L419, L543, L659, L676, L731, L748`
- **위험도**: **중**
- **구조적 원인**:
  I2C1/2/3의 TX/RX DMA 채널 6개(DMA1 Ch1~Ch6), TIM2 PWM DMA 1개(DMA2 Ch3), USART1 RX/TX DMA 2개(DMA2 Ch1, Ch2), USART2 RX/TX DMA 2개(DMA2 Ch4, Ch5)의 하드웨어 우선순위가 예외 없이 모두 `DMA_PRIORITY_LOW`로 초기화되어 있다[^5].
- **공식 기술 규격 검증**:
  ST RM0440 DMA 컨트롤러 사양에 따르면, 복수의 DMA 요청이 동시 발생할 경우 소프트웨어 우선순위(Very High > High > Medium > Low)가 우선 적용되며, 소프트웨어 우선순위가 동일하면 하드웨어 채널 번호(Channel 1 > Channel 2 > ... > Channel n) 순으로 중재(Arbitration)된다[^5].
- **잠재적 영향**:
  4 Mbps 초고속 버스를 담당하는 USART1 TX/RX DMA가 저속 400 kHz I2C DMA 및 디버그 VCP UART와 동일한 `LOW` 우선순위로 설정되어 있어, 다이나믹셀 버스 버퍼 전송 중 I2C DMA 트랜잭션과 버스 매트릭스 경합이 발생할 때 데이터 지연 및 버스 스톨 마진이 축소된다.

### 6. Cortex-M4 실리콘 코어 특성 오인 및 불필요한 L1 D-Cache 조작 매크로 방치
- **위치**: `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/sensor_dxl_service.c:L100-L102, L183-L185, L250-L252, L430-L432`, `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/term_print.c:L105`
- **위험도**: **중**
- **구조적 원인**:
  ```c
  #if defined(__DCACHE_PRESENT) && (__DCACHE_PRESENT == 1U)
    SCB_CleanDCache_by_Addr((uint32_t *)s_tx_buf, len);
  #endif
  ```
- **공식 기술 규격 검증**:
  - STM32G431은 **ARM Cortex-M4F 코어** 기반 MCU이다. ARMv7-M 아키텍처 명세 및 Cortex-M4 Generic User Guide에 따르면 Cortex-M4 코어는 하드웨어 L1 Data Cache(D-Cache) 컨트롤러를 내장하고 있지 않다 (L1 Cache는 Cortex-M7 이상의 상위 아키텍처에 실장됨)[^6].
  - ST 공식 CMSIS 헤더(`core_cm4.h`)에는 `SCB_CleanDCache_by_Addr` 매크로 정의 자체가 존재하지 않는다.
- **잠재적 영향**:
  메인 모션 보드(STM32H743, Cortex-M7) 레거시 코드베이스의 DMA 캐시 일관성(Cache Coherency) 관리 코드가 실리콘 아키텍처 검토 없이 무비판적으로 촉각 센서 펌웨어로 복사되어 잔존하였다. 현재는 `#if` 가드로 인해 컴파일 시 제거되나, 실리콘 하드웨어 스펙에 대한 이해 결여를 드러내는 대표적 아키텍처 안티패턴이다.

### 7. 반이중 UART 트랜시버(SN74LXC2T45) 방향 제어(PF1) 스위칭 지연 마진 리스크
- **위치**: `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/sensor_dxl_service.c:L120-L127` (`dxl_start_tx`), `L254-L255`
- **위험도**: **중**
- **구조적 원인**:
  단일선 반이중 UART 버스 구동을 위해 외부 로직 레벨 시프터 및 버스 트랜시버(`SN74LXC2T45`)를 탑재하고 `PF1` 핀으로 송수신 방향(DIR)을 제어한다[^7].
  ```c
  /* DIR HIGH = MCU-to-bus TX through SN74LXC2T45DCUR. */
  HAL_GPIO_WritePin(USART1_DIR_GPIO_Port, USART1_DIR_Pin, SENSOR_DXL_DIR_TX_STATE);
  if (HAL_HalfDuplex_EnableTransmitter(&huart1) != HAL_OK) {
      HAL_GPIO_WritePin(USART1_DIR_GPIO_Port, USART1_DIR_Pin, SENSOR_DXL_DIR_RX_STATE);
      return HAL_ERROR;
  }
  return HAL_UART_Transmit_DMA(&huart1, s_dxl_tx_buf, size);
  ```
- **공식 기술 규격 검증**:
  TI SN74LXC2T45 데이터시트에 따르면, DIR 입력 신호 인가 후 출력 버퍼가 고임피던스(Hi-Z) 상태에서 정상 구동(Active Drive)으로 전환되는 활성화 시간($t_{en}$) 및 레벨 시프팅 전파 지연($t_{pd}$)이 수십 나노초에서 최대 100 ns 이상 소요된다[^7].
- **잠재적 영향**:
  `PF1` 핀을 `SET`으로 변경한 직후 아무런 하드웨어 안정화 지연 없이 즉시 DMA 송신 레지스터를 가동한다. 만약 트랜시버 버퍼가 완전히 드라이브 상태로 열리기 전에 USART1 시프트 레지스터에서 스타트 비트(Start Bit) 출력이 시작되면, 패킷의 첫 바이트 시작 신호 에지가 완만하게 왜곡되거나 누락되어 수신 측(메인 MCU)에서 프레이밍 에러(Framing Error)가 발생할 수 있다.

### 8. IWDG(독립 워치독) 32 kHz LSI 오실레이터의 하드웨어 주파수 드리프트(최대 +50%/-18.7%) 리스크
- **위치**: `02_V6S_Sensor_FWCube2.1.0/Src/main.c:L532-L554` (`MX_IWDG_Init`)
- **위험도**: **하**
- **구조적 원인**:
  ```c
  hiwdg.Instance = IWDG;
  hiwdg.Init.Prescaler = IWDG_PRESCALER_64;
  hiwdg.Init.Window = 4095;
  hiwdg.Init.Reload = 2500;
  ```
- **공식 기술 규격 검증**:
  - STM32G431 데이터시트의 내부 저속 RC 오실레이터(LSI) 전기적 특성에 따르면, LSI 공칭 주파수는 32 kHz이나 온도($-40^\circ\text{C} \sim +125^\circ\text{C}$) 및 전원 전압 변동에 따라 **26 kHz에서 최대 48 kHz까지 광범위하게 변동(최대 -18.7% ~ +50.0%)**한다[^8].
  - 설정된 타임아웃 주기:
    $$T_{timeout} = \frac{2500 \times 64}{f_{LSI}} = \frac{160000}{f_{LSI}} \approx \begin{cases} 5.000 \text{ s} & (f_{LSI} = 32 \text{ kHz, 공칭}) \\ 3.333 \text{ s} & (f_{LSI} = 48 \text{ kHz, 고온 극단값}) \\ 6.154 \text{ s} & (f_{LSI} = 26 \text{ kHz, 저온 극단값}) \end{cases}$$
- **잠재적 영향**:
  로봇 핸드 관절 및 모터 발열로 인해 센서 보드 온도가 급격히 상승할 경우 LSI 주파수가 빨라져 실제 하드웨어 리셋 타임아웃 주기가 약 3.33초까지 단축된다. 부팅 초기화 루틴이나 장시간 블로킹 루프에서 마진 계산 착오로 인한 불시 IWDG 리셋 리스크가 존재한다.

### 9. I2C GPIO 핀의 저속 슬루율(`GPIO_SPEED_FREQ_LOW`) 설정 및 노이즈 필터링 마진
- **위치**: `02_V6S_Sensor_FWCube2.1.0/Src/stm32g4xx_hal_msp.c:L218, L225, L298, L305, L378, L385`
- **위험도**: **하**
- **구조적 원인**:
  I2C1(PA15, PB7), I2C2(PF0, PA9), I2C3(PA8, PB5) 3개 버스의 총 6개 SDA/SCL 핀 출력 속도가 모두 `GPIO_SPEED_FREQ_LOW`로 초기화되어 있다[^9].
- **공식 기술 규격 검증**:
  ST RM0440 및 STM32G4 I/O 포트 AC 특성에 따르면, `LOW` 속도 설정 시 내부 출력 드라이버의 슬루율(Slew Rate)이 억제된다. 400 kHz Fast-Mode 통신 시 버스 기생 커패시턴스가 높은 긴 연성 케이블(FPCB) 환경에서 신호 상승 에지 지연(Rise Time Exceedance)이 발생할 수 있다[^9].
- **잠재적 영향**:
  손가락 관절 FPCB 배선의 커패시턴스가 누적될 경우, 400 kHz 클록 에지가 왜곡되어 I2C 통신 CRC 또는 NACK 에러 발생 빈도가 증가할 수 있다.

### 10. Alternate I2C 주소(SA0 하드웨어 핀) 플로팅 방어 회로 및 동적 복구 부재
- **위치**: `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Inc/sensor_service_i2c.h:L40-L42`, `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/sensor_service_i2c.c:L85-L107, L348-L365`
- **위험도**: **하**
- **구조적 원인**:
  LPS27HH 센서의 I2C 7비트 주소는 하드웨어 `SA0` 핀 레벨에 따라 `0x5C`(GND 연결) 또는 `0x5D`(VDD 연결)로 결정된다. 펌웨어는 3개 채널 모두 단일 주소(`0x5C`, 8비트 표기 `0xB8`)만을 정적으로 고정하여 초기화하며, 런타임에 대체 주소(`0x5D`) 프로빙이나 자동 복구 루틴을 구비하지 않는다[^10].
- **공식 기술 규격 검증**:
  ST LPS27HH 데이터시트에 따르면 SA0 핀은 내부 풀다운 저항이 없으므로, 외부 납땜 크랙이나 FPCB 패턴 단선 시 핀이 플로팅(High-Z) 상태가 되어 주변 노이즈에 따라 주소가 `0x5C`와 `0x5D` 사이에서 동적으로 흔들릴 수 있다[^10].
- **잠재적 영향**:
  단선이나 냉땜 발생 시 펌웨어는 고정된 단일 주소(`0x5C`)로만 통신을 시도하므로 센서 노드를 영구 오프라인으로 판정하여 센싱 데이터를 완전 상실한다.

### 11. LPS27HH 센서 VDD 전원 제어 FET(Power-Cycle Pin) 부재 및 아날로그 프론트엔드(AFE) 락업 시 물리적 콜드 리셋 불가
- **위치**: `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/sensor_service_i2c.c:L223-L225, L452-L455`, 센서 보드 하드웨어 전원 토폴로지
- **위험도**: **상**
- **구조적 원인**:
  촉각 센서 보드 하드웨어 설계 상 LPS27HH 센서의 VDD 공급선에 전원 차단/재인가용 로드 스위치(P-MOSFET 또는 Load Switch IC)가 실장되어 있지 않고 MCU 3.3V 전원 레일에 상시 직결되어 있다[^11].
- **공식 기술 규격 검증**:
  - 펌웨어 소스코드 주석에서도 본 하드웨어적 결함이 명시되어 있다[^11]:
    ```c
    /* Parked: soft-reset retries exhausted on a channel with no power-cycle pin.
     * Only a manual SWRESET/BOOT (or a future power-cycle wiring) clears this - never silently re-trusted. */
    ```
  - ST LPS27HH 하드웨어 아키텍처 상 내부 아날로그 프론트엔드(MEMS 차지 펌프, 센싱 정전용량 인터페이스 브릿지)가 정전기(ESD)나 급격한 전원 노이즈로 인해 래치업(True Analog Lock-up)에 진입하면, I2C 디지털 레지스터 제어(SWRESET / BOOT)로는 실리콘 레벨의 아날로그 래치가 풀리지 않는다.
- **잠재적 영향**:
  모션 보드나 상위 제어기가 센서 통신 실패를 감지하여 MCU를 소프트웨어 리셋(`NVIC_SystemReset`)하거나 워치독 리셋(IWDG)을 유발하더라도, 센서 VDD 전원은 계속 유지되므로 센서는 영구 락업 상태를 지속한다. 오직 로봇 핸드 전체 전원을 차단하여 VDD를 0V로 완전 방전시키는 **"파워온 리셋(Power-on Reset)"만이 센서를 물리적으로 콜드 리셋**시킬 수 있어, 운용 중 락업 발생 시 전체 전원을 차단하기 전까지 압력 센싱이 영구 정지된다.

### 12. AN5590 파워온 부팅 타이밍 마진 부족(VDD 인가 후 5 ms 지연)으로 인한 NVM 트림 파라미터 로딩 전 I2C 버스 충돌
- **위치**: `02_V6S_Sensor_FWCube2.1.0/V6S_Sense/Src/sensor_service_i2c.c:L419-L425` (`HAL_Delay(5U)`)
- **위험도**: **중**
- **구조적 원인**:
  부팅 시 센서 초기화 전 대기 지연이 단 5 ms(`HAL_Delay(5U)`)로 하드코딩되어 있다[^12].
  ```c
  /* AN5590 Section 6: after VDD is applied, the sensor needs up to 4.5ms
   * (max) to load its trimming parameters; registers are not accessible until then. */
  HAL_Delay(5U);
  ```
- **공식 기술 규격 검증**:
  - ST 공식 애플리케이션 노트 AN5590 Section 6 규격에 따르면, LPS27HH는 VDD 전원이 공급된 후 NVM(비휘발성 메모리)에서 내부 트리밍 파라미터를 레지스터로 로드하는 데 **최대 4.5 ms**가 소요되며, 이 과정이 완료되기 전에는 I2C 레지스터 접근이 하드웨어적으로 금지된다[^12].
  - 전원 공급 레귤레이터의 슬루율(Power Rise Time $t_{VDD}$) 및 손가락 관절 연성 케이블(FPCB)의 기생 커패시턴스로 인해 전원 레일이 3.3V에 완전히 안착하는 데 수 밀리초의 추가 시간이 소요된다.
- **잠재적 영향**:
  FPCB 선로 임피던스나 레귤레이터 개체 편차로 전원 상승이 단 0.5~1 ms만 늦어지는 "특정 보드/특정 포트"의 경우, 5 ms 시점에 센서가 아직 부팅 완료 전 상태임에도 MCU가 I2C `WHO_AM_I` 읽기를 시도하여 즉시 통신 에러가 발생한다. 이는 초기 부팅 실패 후 복구 루틴 진입 및 영구 결함 파킹(`s_declared_faulty`)으로 이어져, 특정 보드에서 파워온 시 간헐적으로 압력이 읽히지 않는 개체 편차 결함을 초래한다.

### 13. 완제품 조립 후 외부 물리 접근 불가 및 메인 MCU 연결 버스(USART1) 기반 펌웨어 다운로드 경로 부재
- **위치**: `reference/v6-tactile-sensor/V6_IAP_G431_Sensor_MCU/00_IAP_STM32G4_FWCube2.1.0/Src/main.c:L73-L85`, 로봇 핸드 물리 배선 토폴로지
- **위험도**: **상**
- **구조적 원인**:
  촉각 센서는 손가락 끝마디(Fingertip) 내부에 물리적으로 몰딩·조립되어 외부 디버그 헤더(SWD)나 별도 통신 핀으로의 물리적 접근이 원천 차단된다. 완제품 상태에서 핸드 메인 MCU(STM32H743)와 센서 MCU 간에 물리적으로 연결된 유일한 시리얼 배선은 **`USART1` (반이중 4 Mbps DXL 단일선 버스, PB6 / SN74LXC2T45)**뿐이다. 그러나 현재 부트로더(`00_IAP`)는 외부에서 접근할 수 없는 **`USART2` (PA2/PA3, PC 터미널 직결용)**만을 수신하도록 하드코딩되어 있어 메인 MCU를 통한 인시스템 펌웨어 갱신이 불가능하다[^13].

  - `V6_IAP_G431_Sensor_MCU` 부트로더 소스코드에 따르면, 하드웨어 초기화가 `USART2` 단일 채널에만 국한되어 있으며, 메인 MCU와 연결된 `USART1` (반이중 방향 전환 핀 PF1 제어 포함) 수신 스택이 전무하다[^13].
  - 임베디드 유지보수성 및 기능 안전 표준에 따르면, 분해가 불가능한 밀폐형 센서 노드는 필드 업데이트(IAP)를 위해 상위 마스터 제어기와의 상시 연결 버스를 통한 펌웨어 주입 경로를 필수적으로 확보해야 한다.
- **잠재적 영향**:
  로봇 핸드 조립 완료 후 센서 펌웨어의 버그 수정이나 보정 알고리즘 개선이 필요할 때, 손가락 기구물을 물리적으로 파괴·분해하지 않고는 펌웨어를 갱신할 수 없다. 이는 양산성 및 필드 유지보수성에 치명적인 구조적 한계로 작용한다.

## 3. 결론 및 하드웨어/소프트웨어 설계 권고

1. **메인 MCU 연결 버스(`USART1`) 기반 IAP 다운로드 포트 단일화 및 개정**:
   `USART2` 디버그 포트에 고정된 기존 부트로더를 개정하여, 메인 MCU와 물리적으로 상시 직결된 **`USART1` (반이중 DXL 단일선 버스)**를 통해 메인보드(STM32H743)가 각 센서 노드로 펌웨어 바이너리를 직접 스트리밍 및 다운로드할 수 있도록 부트로더 수신 인터페이스를 반드시 수정·통합해야 한다.
2. **센서 VDD 전원 스위칭 FET(Power-Cycle 회로) 추가**:
   센서 ASIC 내부 아날로그 프론트엔드 래치업 발생 시 시스템 전체 전원을 차단하지 않고도 MCU GPIO 제어를 통해 센서 VDD만을 독립적으로 콜드 리셋할 수 있도록, 차기 하드웨어 리비전에서 센서 VDD 라인에 P-채널 MOSFET 또는 로드 스위치를 필히 실장해야 한다.
3. **부팅 전원 안정화 대기 시간(Power-on Margin) 확장**:
   FPCB 전원 인가 슬루율 및 AN5590 NVM 부트 마진을 확보하기 위해, 부팅 대기 시간을 최소 **20 ms** 이상으로 확장하여 특정 보드의 초기 I2C 프로빙 충돌을 원천 차단해야 한다.
4. **플래시 파라미터 저장 파이프라인 분리**:
   Single-Bank Flash의 버스 스톨 특성을 고려하여, 로봇 운용 중(`Active Motion`)에는 플래시 쓰기를 엄격히 차단하고, 캘리브레이션 전용 모드 또는 정지 상태에서만 저장을 수행하도록 상위 프로토콜을 통제해야 한다.
5. **선점형 NVIC 우선순위 계층화**:
   20개 인터럽트의 `Priority 0, 0` 플랫 구조를 해체하고, 초고속 반이중 UART DXL 통신을 최우선(`0`), I2C DMA 및 센서 인터럽트를 차순위(`1`), 타이머 및 시스템 인터럽트를 하위(`2~3`)로 계층화해야 한다.
6. **USART1 하드웨어 FIFO 활성화**:
   4 Mbps 고속 통신 시 ORE를 방지하기 위해 `HAL_UARTEx_EnableFifoMode(&huart1)`를 호출하여 8바이트 하드웨어 FIFO를 가동해야 한다.
7. **트랜시버 방향 제어 핀 지연 마진 확보**:
   `PF1` DIR 핀을 TX로 전환한 직후 최소 수십 나노초의 지연 마진을 보장한 후 DMA 송신을 트리거해야 한다.
