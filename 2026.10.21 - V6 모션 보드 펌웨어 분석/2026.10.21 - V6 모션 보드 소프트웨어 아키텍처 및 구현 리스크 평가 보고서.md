# V6 모션 보드 소프트웨어 아키텍처 및 구현 리스크 평가 보고서

## 1. 개요

V6 모션 제어 시스템은 다관절 분산 액추에이터 제어, 호스트 통신, 고주기 센서 피드백을 실시간으로 통합 처리한다. 

본 보고서는 반도체 제조사가 제공하는 기본 HAL 및 하드웨어 드라이버 계층을 제외하고, **순수 사용자 애플리케이션 계층**을 대상으로 시스템의 신뢰성과 실시간 결정론을 위협하는 구조적 한계와 소프트웨어 결함을 종합 평가한다. 시스템 전반의 구조적 취약점을 야기하는 **양대 근본 아키텍처 결함(정적 모놀리식 강결합 및 동적 스케줄링 주객 전도)**을 서두에서 총괄 분석한 후, 런타임 제어 루프의 파탄을 유발하는 **Part 1. 실시간 제어 파이프라인 및 시스템 설계 리스크(5대 항목)**와, 메모리 안전성 및 데이터 무결성을 훼손하는 **Part 2. 세부 구현 결함 및 코드 레벨 리스크(12대 항목)**로 체계화하여 총 17대 핵심 리스크를 분석한다.

> [!CAUTION]
> 본 보고서는 펌웨어 소스코드와 구현 로직, 산업 표준 소프트웨어 공학 규격에 기반한 정적 코드 분석 결과이므로, 실제 하드웨어 런타임 스케줄러 환경에 따라 영향도에 차이나 예외가 존재할 수 있다. 또한 본 분석 결과가 대상 시스템의 모든 잠재적 소프트웨어 결함과 안티패턴을 전수 검출했음을 보장하지 않는다.

## 2. 주요 리스크 분석

### 2.1 시스템 구조적 특성 및 아키텍처 결함

본 시스템의 구조적 취약점은 코드베이스 전반에 걸친 **1) 정적 구조 차원의 계층화 부재(모놀리식 강결합)**와 **2) 런타임 스케줄링 차원의 하드웨어 타이머 종속(가변 주기화)**에서 비롯되며, 이는 **3) 소프트웨어 내부 공학 품질 및 최종 제품의 운용 신뢰성 저하**로 이어진다.

#### 2.1.1. 계층화 부재 및 모놀리식 강결합 아키텍처
- **위치**: `STM32CubeIDE/Application/User/finger_dxl/finger_bus_master.c` (3,872 라인), `STM32CubeIDE/Application/User/modbus/mb_joint_control.c`, `Core/Src/main.c`
- **구조적 특성**:
  하드웨어 추상화 계층, 통신 드라이버, 상위 제어기, 프로토콜 스택 간의 모듈 경계가 명확하지 않아 단일 소스에 의존성이 집중된 모놀리식 구조(Big Ball of Mud 패턴)를 띤다.[^1]
- **주요 결합 양상**:
  `finger_bus_master.c`(3,872 라인) 단일 파일 내에 복수의 기능이 결합되어 있다:
  1. **물리 계층 제어**: 5개 채널 UART의 DMA 링버퍼 오프셋 계산, 하드웨어 플래그 클리어, D-Cache Invalidate 호출을 드라이버 내부에서 직접 수행한다.
  2. **프로토콜 파싱 및 패킷 분기 혼재**: DXL 모터 패킷 송수신 루틴 내부에서 촉각 센서 패킷을 식별하여 가로채는 로직이 결합되어 있다.
  3. **제어 및 파라미터 관리 결합**: 드라이버 내부에서 Modbus 레지스터를 조작하고, 모터 게인 설정 시퀀스 및 Flash 메모리 저장 인터페이스를 직접 호출한다.
  4. **전역 데이터 공유**: 스케줄러(`finger_task.c`), Modbus 인터페이스(`mb_joint_control.c`), 메인 루프(`main.c`)가 드라이버 내부 전역 구조체와 버퍼를 직접 참조한다.
- **엔지니어링 영향**:
  모듈 간 독립성이 낮아 특정 프로토콜 수정 시 연쇄적인 코드 변경이 필요하며, 하드웨어 인터페이스 직접 참조로 인해 PC 환경에서의 모듈 단위 테스트 구축이 제한된다.

#### 2.1.2. 하드웨어 타이머와 통신 시퀀서의 결합
- **위치**: `Core/Src/main.c:L891-L903`, `STM32CubeIDE/Application/User/finger_dxl/finger_task.c:L185-L290`
- **구조적 특성**:
  독립적인 시간 기준(Timebase)을 공급해야 할 기본 타이머(`TIM6`)의 레지스터를 통신 시퀀스 상태 머신(`finger_task`)이 직접 변경하여 동작 주기를 제어하는 결합 구조를 취한다.
- **주요 결합 양상**:
  1. **타이머 레지스터 동적 변경과 통신 시퀀스 결합**:
     다이나믹셀 패킷 송수신 단계(1차 구동 $\rightarrow$ 1차 수신 대기 $\rightarrow$ 2차 구동 $\rightarrow$ 2차 수신 대기)마다 타이머 자동 재로드 레지스터(`ARR`)를 249 µs로 재설정하고 카운터(`CNT`)를 0으로 리셋하여 시퀀스를 진행한다.
  2. **인터럽트 처리 시간에 종속적인 가변 주기**:
     인터럽트 진입 시 `__HAL_TIM_DISABLE()`로 타이머를 정지하고, ISR 처리 완료 후 `__HAL_TIM_ENABLE()`로 재가동한다. 이에 따라 실제 주기($T_s$)는 설정값에 인터럽트 실행 시간과 선점 지연이 가산되어 변동하며, 등간격 샘플링을 가정한 이산 시간 제어 루프의 주기 안정성에 영향을 미친다.
  3. **상태 머신 전이 지연 시 제어 루프 동결**:
     통신 노이즈나 응답 지연으로 상태 머신 천이가 중단되거나 지연될 경우, 타이머 인터럽트에 종속되어 있는 관절 제어 연산(`jc_step()`)도 함께 지연되거나 중단되는 구조적 의존성을 가진다.
- **엔지니어링 영향**:
  모터 수량이나 통신 패킷 길이가 변경될 경우 타이머 타임슬롯 설정을 재산출해야 하므로 확장성이 낮고, 인터럽트 처리 시간에 따른 지터가 제어 주기에 직접 반영된다.

#### 2.1.3. 구조적 결함이 소프트웨어 및 제품 품질에 미치는 영향

계층화 부재(정적 결합)와 타이머-통신 시퀀서 결합(동적 결합)은 소프트웨어 내부 공학 품질과 최종 로봇 핸드 제품의 운용 신뢰성에 다음과 같은 기술적 영향을 미친다:

1. **소프트웨어 공학적 품질(내부 품질) 영향**:
   - **단위 테스트 및 가상 시뮬레이션 환경 구축 불가**:
     하드웨어 레지스터 및 전역 변수에 직접 결합되어 있어, 타깃 하드웨어가 없는 호스트 PC 환경에서의 가상 시뮬레이션(Software-in-the-Loop) 및 모듈별 단위 테스트 자동화 구축이 어렵다.
   - **수정 부작용(Side Effect) 추적 난해**:
     단일 소스 집중 및 모듈 간 전역 메모리 공유로 인해, 통신 패킷 구조나 제어기 로직 수정 시 시스템 전반에 미치는 영향 범위를 사전에 예측하기 어렵다.
   - **이식성 및 재사용성 제한**:
     특정 MCU 타이머(`TIM6`) 레지스터 조작 및 전용 DMA 버퍼 구조에 종속되어 있어, 신규 칩셋이나 RTOS 기반 아키텍처로의 전환 시 코드 재사용률이 낮다.

2. **제품 및 운용 품질(외부 품질) 영향**:
   - **모션 제어 정밀도 저하 (샘플링 지터 및 토크 왜곡)**:
     인터럽트 실행 시간에 따른 제어 주기 변동(지터)과 전역 메모리 동시성 경합에 따른 데이터 찢김이 발생하여, 정밀 임피던스 제어 시 미세한 토크 리플과 진동을 유발할 수 있다.
   - **결함 전파에 따른 작업 가용성 저하**:
     물리적으로 분리된 5개 UART 채널이 소프트웨어 락스텝 루프로 결합되어 있어, 1개 손가락 선로의 일시적 통신 지연이나 패킷 이상이 전체 핸드의 제어 루프 동결(Livelock)로 확대된다.
   - **필드 장애 분석 비용 증가**:
     패킷 에러 플래그 마스킹 및 비동기 동시성 경합 상태는 재현이 어려운 간헐적 결함으로 발현되어 현장 문제 원인 규명에 소요되는 분석 비용을 증가시킨다.
   - **파생 기종 확장 한계**:
     손가락 수량 변경, 신규 센서 추가, 통신 주기 변경 등 제품 라인업 확장 시 아키텍처의 유연성이 부족하여 펌웨어 전반의 수작업 재설계를 요구한다.

### 2.2 세부 위험도 분류 체계 및 판정 기준

상기 매크로 아키텍처 결함의 토양 위에서 파생된 개별 실시간 설계 리스크와 코드 레벨 결함을 시스템 안전성, 실시간 결정론, 데이터 무결성에 미치는 영향도에 따라 3단계 위험도 체계로 분류하여 평가한다.

| 위험도 등급 | 심각도 정의 |
| :--- | :--- |
| **상** | 즉각적인 제어 루프 파탄, 모터 오동작 및 파손, 동시성 데이터 찢김, 시스템 에러 은폐, 스케줄러 데드락을 초래하는 치명적 결함 |
| **중** | 제어 주기 타이밍 지터 유발, 통신 오버헤드 누적, C 표준 미정렬 캐스팅, 가독성 및 유지보수성을 심각하게 저해하는 안티패턴 |
| **하** | 결합도 증가, 잠재적 부동소수점 특이점, 코드 관리 부실 등 정상 조건에서 즉각적인 제어 실패를 유발하지 않는 구현 한계 |

### 2.3 Part 1. 실시간 제어 파이프라인 및 시스템 설계 리스크

#### 1. 하드웨어 타이머 인터럽트 핸들러 내 고부하 다체 역학 연산 직접 실행
- **위치**: `Core/Src/main.c:L888-L904`, `STM32CubeIDE/Application/User/finger_dxl/finger_task.c:L210-L215`, `STM32CubeIDE/Application/User/control/joint_control.c:L255-L332`
- **위험도**: **상**
- **아키텍처 결함 분석**:
  하드웨어 기본 타이머인 `TIM6` 인터럽트 서비스 루틴(`HAL_TIM_PeriodElapsedCallback`)의 실행 컨텍스트 내부에서 상위 다체 역학 제어기인 `jc_step()`을 직접 동기 실행한다. 기본 상태에서는 조기 반환되지만, 호스트가 Modbus나 통신 명령을 통해 중력 보상, H-무한대, 임피던스 제어 모드를 활성화하는 순간 16개 이상 관절의 재귀 뉴턴-오일러 알고리즘, 팁 임피던스 제어, H-무한대 상태 공간 필터링, 다수의 삼각함수 연산, 디버그용 `printf()` 블로킹 출력까지 포함하는 고부하 제어 연산 루틴이 매 틱마다 고우선순위 인터럽트 내부에서 실행된다.
- **소프트웨어 공학 및 실시간 표준 검증**:
  실시간 임베디드 운영체제 원칙에 따르면, 하드웨어 인터럽트 핸들러는 외부 인터럽트 플래그 클리어 및 최소한의 데이터 복사만 수행하고, 계산 집약적 알고리즘은 워커 태스크나 메인 루프로 지연 처리해야 한다.[^2][^3]
- **잠재적 영향**:
  모드 활성화 시 단일 인터럽트 핸들러 실행 시간이 수백 마이크로초 단위로 크게 증가하여 하드웨어 인터럽트 컨텍스트를 장시간 독점한다. 이로 인해 4 Mbps 고속 UART DMA 수신 완료 인터럽트, W6300 이더넷 통신 인터럽트의 응답 지연 지터를 유발하고 수신 FIFO 오버런을 발생시켜 전체 실시간 제어 루프의 결정론을 훼손한다.

#### 2. 동적 타이머 레지스터 조작 및 인터럽트 내 타이머 정지로 인한 누적 위상 지연
- **위치**: `Core/Src/main.c:L891-L903`, `STM32CubeIDE/Application/User/finger_dxl/finger_task.c:L185-L186, L204-L205, L263-L264, L275-L276, L285-L286`
- **위험도**: **상**
- **아키텍처 결함 분석**:
  제2.1.2항에서 식별된 동적 스케줄링 결함의 구체적 메커니즘이다. 고정 주기 타임 트리거드 스케줄러를 사용하는 대신, 단일 하드웨어 타이머(`finger_task_htim`, 실제 `htim6`)의 자동 재로드 레지스터(`ARR`)를 상태 머신 천이마다 `__HAL_TIM_SET_AUTORELOAD()`, `__HAL_TIM_SET_COUNTER(..., 0)`로 덮어쓰는 동적 조작 구조를 채택했다. 또한 `HAL_TIM_PeriodElapsedCallback` 진입 즉시 `__HAL_TIM_DISABLE(htim)`으로 하드웨어 카운터를 멈추고, `finger_task()` 실행 종료 시점에 비로소 `__HAL_TIM_ENABLE(htim)`으로 타이머를 재가동한다.
- **소프트웨어 공학 및 실시간 표준 검증**:
  ISO 26262 및 IEC 61508-3 소프트웨어 타이밍 아키텍처 규격에 따르면, 제어 주기를 결정하는 하드웨어 타이머 베이스는 런타임에 정지되거나 동적으로 재프로그래밍되어서는 안 되며, 결정론적 불변 주파수를 엄격히 유지해야 한다.[^4]
- **잠재적 영향**:
  매 주기마다 `finger_task()`의 실행 시간(수십~수백 µs)만큼 하드웨어 타이머 카운터가 완전히 정지되므로, 제어 주기가 소프트웨어 실행 시간에 비례하여 영구적으로 지연 누적되는 누적 위상 지연이 발생한다. 또한 `ARR` 동적 재설정과 인터럽트 플래그 처리 간의 불일치 시 카운터가 오버플로우되어 최대 65,535 틱 동안 인터럽트가 중단되는 타이머 잠금 취약점이 상존한다.

## 3. 제어 연산 파이프라인 최적화 및 실행 부하 완화 방안

본 절에서는 제어 연산(`jc_step()`)의 실행 시간을 단축하기 위해, `control/` 모듈 코드를 대상으로 **1) 계산 절차 축소**와 **2) 명령어 수준 가속** 방안을 도출한다. 타깃 MCU인 STM32H743(ARM Cortex-M7)은 부동소수점(Float) 벡터 SIMD(NEON/Helium) 하드웨어를 지원하지 않으므로 부동소수점 벡터화는 배제하고, 스칼라 FPU 파이프라인 활용과 수식 간소화를 중심으로 검토한다.

### 3.1. 알고리즘 및 계산 절차 축소 

#### 1. 정적 RNEA 수식 단순화 (`gravity_comp.c`)
- **원인 분석**:
  `grav_rnea_one_finger()`는 일반 다체 동역학 RNEA 알고리즘 구조를 사용하나, 정적 중력 보상 조건에서는 관절 속도와 가속도가 0(`/* qd = qdd = 0 */`)으로 고정된다. 따라서 각속도(`omega`)와 각가속도(`alpha`)는 `{0, 0, 0}`이다.
- **최적화 조치**:
  $\omega = 0, \alpha = 0$ 조건을 대입하여 결과가 0인 연산 블록을 제거한다:
  - 전진 패스: 원심력 및 코리올리 가속도 외적(`cross3` 6회)을 제외하고, 중력 가속도 회전 변환만 수행한다 ($a_i = R_i^T a_{i-1}$, $a_{c,i} = a_i$).
  - 후진 패스: 관성 모멘트 행렬 곱(`matvec3` 2회) 및 자이로스코픽 외적(1회)을 제외하고, 정적 중력 힘($F_i = m_i a_{c,i}$)과 정적 모멘트($m_i = c_i \times F_i + m_{child} + r \times f_{child}$)만 계산한다.
- **연산 절감량**: `gravity_comp.c`의 부동소수점 연산량(FLOPs)을 약 65% 절감한다 (20개 관절 기준 약 1,200 FLOPs 감소).

#### 2. IMU 쿼터니언 회전행렬 변환 범위 축소 (`joint_control.c`)
- **원인 분석**:
  `jc_update_orientation_from_imu()`는 자세 벡터 `up_i` 산출을 위해 3x3 회전행렬 $R_{imu}$의 9개 원소를 모두 계산한다. 그러나 후속 로직에서 참조하는 값은 세 번째 행(`R_imu[6], [7], [8]`) 3개뿐이며, 나머지 6개 원소는 참조하지 않는다.
- **최적화 조치**:
  미사용 원소(`R_imu[0]` ~ `R_imu[5]`)의 계산을 제외하고 세 번째 행의 3개 원소만 산출하도록 변경한다.
- **연산 절감량**: 해당 변환 루틴의 부동소수점 연산을 67% 절감한다 (곱셈 12회, 뺄셈 6회 감소).

#### 3. 임피던스 목표 위치 산출용 기구학 함수 분리 (`impedance_ctrl.c`)
- **원인 분석**:
  `imp_update_finger()`는 목표 손끝 위치 $x_{ref}$ 산출 시 순방향 기구학과 기하 자코비안을 모두 연산하는 `hk_fk_jacobian()`을 호출한 후 자코비안 출력 버퍼(`J_unused`)를 참조하지 않고 버린다.
- **최적화 조치**:
  손끝 위치만 산출하는 별도 함수(예: `hk_fk_pos()`)를 정의하여 자코비안 외적 루프($J[:, i] = z_i \times (p_{ee} - p_i)$)를 제외한다.
- **연산 절감량**: $q_{ref}$ 대상 기구학 연산량을 약 40% 절감한다.

#### 4. H-무한대 제어 이득 나눗셈 사전 계산 (`hinf_ctrl.c`)
- **원인 분석**:
  `hinf_update()`는 20개 관절에 대해 제어 주기마다 `k_scale = s_k[idx] + 1.0f / (s_gamma[idx] * s_gamma[idx])`를 계산한다. 파라미터 `s_k`와 `s_gamma`가 고정값임에도 하드웨어 부동소수점 나눗셈(`FDIV.F32`)을 주기마다 반복 실행한다.
- **최적화 조치**:
  게인 설정 시점에 `s_k_scale[20]` 배열을 사전 계산하여 저장하고, 제어 루프에서는 해당 배열을 직접 참조한다.
- **연산 절감량**: 제어 틱당 FPU 부동소수점 나눗셈 20회를 제거한다.

### 3.2. 명령어 및 마이크로아키텍처 수준 가속 

#### 1. `sincosf` 내장 함수를 통한 삼각함수 호출 결합 (`gravity_comp.c`, `hand_kin.c`)
- **개선 방안**:
  `axis_angle()` 등에서 동일 입력 각도 $q$에 대해 `cosf(q)`와 `sinf(q)`를 개별 호출하는 구조를 GCC 내장 함수 **`sincosf(q, &s, &c)`**로 대체한다.
- **효과**: 공통 인자 축소 및 코어 연산을 공유하여 삼각함수 연산 소요 시간을 단축한다.

#### 2. 조건 분기 없는 클램핑 명령어 적용 (`joint_control.c`, `hinf_ctrl.c`)
- **개선 방안**:
  관절별 전류/토크 클램프 루틴의 `if-else` 분기문을 하드웨어 포화 매크로(`__SSAT`) 또는 FPU 비교/선택 명령어(`VMINNM.F32`, `VMAXNM.F32`)를 유도하도록 변경한다.
- **효과**: 조건 분기문을 줄여 Cortex-M7 파이프라인의 분기 예측 실패 페널티를 완화한다.

#### 3. 기하 연산 함수 인라인 처리 및 FMA 활용 유도
- **개선 방안**:
  `add3`, `scale3`, `dot3`, `cross3`, `matvec3` 등 3차원 기본 벡터/행렬 연산 함수를 인라인화(`always_inline`)한다.
- **효과**: 함수 호출 및 스택 프레임 생성 오버헤드를 제거하고, 컴파일러가 FMA(`VFMA.F32`) 명령어를 생성하여 연산 파이프라인을 효율화하도록 유도한다.

#### 4. 고정 크기 관절 루프 언롤링 (Loop Unrolling)
- **개선 방안**:
  손가락당 관절 수(`HM_NOJ = 4`)가 고정되어 있으므로 컴파일러 언롤링 지시자(`#pragma GCC unroll 4`)를 적용한다.
- **효과**: 루프 인덱스 연산 및 분기 오버헤드를 제거한다.

### 3.3. 개선안 반영 시 예상 효과

3. **알고리즘적 동치성 및 수치 정밀도 고려사항**:
   - 기구학 및 동역학 모델의 기본 수식 구조를 보존하므로 기존 제어 게인을 그대로 활용할 수 있다. 단, FMA(`VFMA`) 결합 연산이나 `sincosf` 적용 시 부동소수점 반올림 순서 변경에 따라 LSB 단위의 미세한 수치 차이가 발생할 수 있으므로 단위 테스트를 통한 출력 검증이 필요하다.
