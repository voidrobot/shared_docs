# V6 모션 보드 하드웨어 및 실리콘 계층 아키텍처 리스크 평가 보고서

## 1. 개요 

본 보고서는 상위 제어 알고리즘이나 상태 머신 로직을 배제하고, **실리콘 내부 버스 아키텍처, MPU 메모리 보호 및 캐시 정책, 하드웨어 타이머 동작 특성, 인터럽트 우선순위 계층, 물리 계층 신호 무결성**의 관점에서 시스템의 신뢰성과 실시간성을 저해할 수 있는 14대 하드웨어 아키텍처 리스크를 평가한다.

> [!CAUTION]
> 본 보고서는 펌웨어 소스코드와 레지스터 설정, 제조사 공식 사양에 기반한 정적 분석 결과이므로, 실물 PCB의 외부 회로 환경에 따라 실제 런타임 영향도에 차이나 예외가 존재할 수 있다. 또한 본 분석 결과가 대상 시스템의 모든 잠재적 하드웨어 및 실리콘 리스크를 전수 검출했음을 보장하지 않는다.

---

## 2. 주요 리스크 분석

본 절에서는 식별된 14대 하드웨어 및 실리콘 아키텍처 리스크를 시스템 안전성, 실시간 제어 주기성, 데이터 무결성에 미치는 영향도에 따라 3단계 위험도 체계로 분류하여 평가한다.

### 위험도(Risk Level) 분류 체계 및 판정 기준

| 위험도 등급 | 심각도 정의 |
| :--- | :--- |
| **상** | 즉각적인 시스템 동결(Lock-up), 메모리 오염, 장시간 제어 공백 또는 물리적 안전 사고를 초래할 수 있는 치명적 설계 결함 |
| **중** | 제어 주기 위상 지터 누적, 고속 통신 프레임 손실, 우선순위 역전 등 시스템 신뢰성과 제어 성능을 유의미하게 저하시키는 리스크 |
| **하** | 잠재적 예외 발생 가능성 또는 버스 대역폭 비효율을 내포하나, 정상 운용 조건에서 즉각적인 제어 중단을 유발하지 않는 구조적 한계 |

### 1. 가변 주기 타이머의 AutoReload Preload 비활성화
- **위치**: `Core/Src/tim.c:L206` (`MX_TIM7_Init`)
- **위험도**: **상**
- **구조적 원인**:
  ```c
  htim7.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_DISABLE;
  ```
- **공식 기술 규격 검증**:
  ST RM0433 타이머 사양에 따르면, Preload가 비활성화된 상태에서 `ARR` 레지스터 값을 직접 변경할 때 타이머의 현재 카운터(`CNT`) 값이 새로 기록된 `ARR` 값보다 크면 카운터는 비교 일치를 건너뛰고 16비트 최대치(65,535)까지 계수한 후 오버플로우해야 다음 갱신 이벤트를 발생시킨다.[^5]
- **잠재적 영향**:
  `finger_task.c`는 런타임에 `__HAL_TIM_SET_AUTORELOAD`를 호출하여 449µs, 249µs, 999µs로 주기를 빈번하게 바꾼다. 카운터가 새 주기보다 앞선 순간 주기가 갱신되면 약 65.5ms 동안 제어 루프가 인터럽트를 발생시키지 못하고 동결되는 심각한 제어 공백이 발생한다.

### 2. 일반 운용 모드에서 독립 워치독(IWDG) 완전 정지
- **위치**: `STM32CubeIDE/Application/User/common/ota_core.c:L175`, `ota_core.h:L90`
- **위험도**: **상**
- **구조적 원인**:
  독립 하드웨어 워치독(IWDG)은 오직 펌웨어 업데이트 직후의 `OTA TRIAL` 부팅 시(20초)에만 가동되며, 정상 모드 운용 중에는 비활성화 상태를 유지한다.
- **공식 기술 규격 검증**:
  산업용 임베디드 안전 표준(IEC 61508 / ISO 13849) 및 ST AN4838은 액추에이터를 구동하는 시스템에서 런타임 락업을 방지하기 위해 독립 하드웨어 워치독의 상시 감시를 요구한다.[^11]
- **잠재적 영향**:
  고전류 다관절 액추에이터를 제어하는 로봇 핸드에서, 정상 운용 중 노이즈나 데드락으로 CPU가 정지하면 시스템을 재부팅할 수단이 없다. 모터 토크가 인가된 상태로 영구 정지하여 기계적 충돌이나 화재 위험에 노출된다.

### 3. 모션 제어 타이머(TIM7)의 저우선순위 설정으로 인한 NVIC 우선순위 역전
- **위치**: `Core/Src/tim.c:L295`
- **위험도**: **중**
- **구조적 원인**:
  ```c
  HAL_NVIC_SetPriority(TIM7_IRQn, 11, 0);
  ```
  시스템 핵심 제어 루프인 TIM7 인터럽트 우선순위가 **`11`**로 설정되어 있다.
- **공식 기술 규격 검증**:
  Cortex-M7 NVIC 아키텍처에서 번호가 낮은 우선순위가 높은 선점권을 갖는다.[^6]
  - DMA1/DMA2 스트림: 우선순위 `2`
  - UART 핑거 버스: 우선순위 `3`
  - RS-485 통신: 우선순위 `5`
  - **디버그 콘솔 CLI (USART3): 우선순위 `10`**
  - **메인 제어 루프 (TIM7): 우선순위 `11`**
- **잠재적 영향**:
  디버그 쉘로 긴 문자열이 입출력되면, 우선순위가 더 높은 USART3 인터럽트 처리에 의해 모션 제어 루프(TIM7)가 선점당해 지연된다. 모터의 실시간 토크 지령 갱신이 디버그 콘솔 통신에 의해 간헐적으로 밀리는 구조적 우선순위 역전이다.

### 4. 타이머 ISR 내부 타이머 강제 정지로 인한 누적 위상 지터 (Phase Drift)
- **위치**: `Core/Src/main.c:L891-L904` (`HAL_TIM_PeriodElapsedCallback`)
- **위험도**: **중**
- **구조적 원인**:
  ```c
  __HAL_TIM_DISABLE(htim);
  finger_task();
  __HAL_TIM_CLEAR_FLAG(htim, TIM_FLAG_UPDATE);
  __HAL_TIM_ENABLE(htim);
  ```
- **공식 기술 규격 검증**:
  주기적 제어 시스템에서 타이머는 하드웨어 프리런(Free-running) 카운터로 유지되어야 누적 위상 오차를 방지할 수 있다.[^5]
- **잠재적 영향**:
  `finger_task()` 실행 시간(수십~수백 µs) 동안 하드웨어 클록 카운트가 정지하므로, 실제 제어 주기는 `설정 주기 + 태스크 연산 시간`으로 실시간 늘어난다. 연산량 변동에 따라 제어 주기가 불규칙하게 변동하며 타이밍 지터(Jitter)를 유발한다.

### 5. UART 내장 하드웨어 FIFO 인위적 비활성화
- **위치**: `Core/Src/usart.c:L100, L171, L242, L313, L384`
- **위험도**: **중**
- **구조적 원인**:
  ```c
  HAL_UARTEx_DisableFifoMode(&huart4);
  ```
- **공식 기술 규격 검증**:
  ST RM0433 USART 규격에 따르면, 내장 16바이트 FIFO는 고속 전송 환경에서 인터럽트 레이턴시 및 DMA 요청 지연에 따른 데이터 손실을 완충하도록 설계되었다.[^8]
- **잠재적 영향**:
  4 Mbps 고속 전송 환경에서 1바이트 수신 주기는 2.5µs에 불과하다. FIFO가 비활성화되어 있으면 DMA 버스 점유가 수 마이크로초 지연되는 것만으로도 수신 오버런 에러(`ORE`)가 발생하여 통신 인터페이스 중단이 발생한다.

### 6. 고속 QUADSPI 통신 핀의 저속 슬루율 설정 (`GPIO_SPEED_FREQ_LOW`)
- **위치**: `Core/Src/quadspi.c:L98-L114`
- **위험도**: **중**
- **구조적 원인**:
  W6300 이더넷 컨트롤러와 고속 통신을 수행하는 QUADSPI 핀 6개(`PB2`, `PE7~10`, `PC11`)의 GPIO 속도가 `GPIO_SPEED_FREQ_LOW`로 초기화되어 있다.
- **공식 기술 규격 검증**:
  ST RM0433 및 STM32H743 데이터시트의 I/O AC 특성에 따르면, `LOW` 속도 설정 시 출력 드라이버의 신호 상승/하강 시간(Rise/Fall Time)이 길어져 수십 MHz 클록 전송 시 신호 에지가 완만해지고 왜곡된다.[^7]
- **잠재적 영향**:
  이더넷 프레임 전송 및 OTA 펌웨어 데이터 스트리밍 시 신호 무결성이 저하되어 패킷 CRC 에러 및 재전송 부하를 유발한다.

### 7. Half-Duplex 방향 제어 핀의 NOP 루프 대증적 딜레이
- **위치**: `STM32CubeIDE/Application/User/finger_dxl/finger_bus_master.c:L1194-L1228`
- **위험도**: **중**
- **구조적 원인**:
  ```c
  FINGER_DIR_TX(finger_num);
  for (volatile int i = 0; i < 100; i++) {
      __NOP();
  }
  ```
- **공식 기술 규격 검증**:
  하드웨어 트랜시버 방향 전환 지연 시간은 외부 로직 레벨 변환기 및 송수신기 IC의 하드웨어 전파 지연 사양(Prop Delay)을 기준으로 정밀 동기화해야 한다.[^8]
- **잠재적 영향**:
  컴파일러 최적화 수준이나 캐시 상태에 따라 100회 NOP 루프의 실제 지연 시간이 변동된다. 트랜시버가 완전히 송신 모드로 활성화되기 전 DMA 송신이 시작되면 패킷 첫 바이트 앞단이 잘려나가는 하드웨어 신호 왜곡 및 패킷 손실 리스크가 발생할 수 있다.

### 9. Non-cacheable 메모리 영역에 대한 불필요한 캐시 유지보수 API 중복 호출
- **위치**: `Core/Src/main.c:L1175-L1180` (`MPU_Config`), `finger_bus_master.c:L855`
- **위험도**: **중**
- **구조적 원인**:
  ```c
  MPU_InitStruct.Number = MPU_REGION_NUMBER1;
  MPU_InitStruct.BaseAddress = 0x30000000;
  MPU_InitStruct.Size = MPU_REGION_SIZE_256KB;
  MPU_InitStruct.TypeExtField = MPU_TEX_LEVEL1;
  HAL_MPU_ConfigRegion(&MPU_InitStruct);
  ```
  `MPU_InitStruct` 구조체는 이전 Region 0의 `IsCacheable = 0`, `IsBufferable = 0`, `IsShareable = 1` 값을 상속받아 `TypeExtField`를 `MPU_TEX_LEVEL1 (b001)`로 설정한다.
- **공식 기술 규격 검증**:
  ARMv7-M 아키텍처 공식 명세에 따르면, `TEX=b001, C=0, B=0, S=1` 인코딩은 **Normal Memory, Outer and Inner Non-cacheable, Shareable** 모드를 의미한다.[^1][^2] 즉, D2 SRAM(0x30000000 ~ 0x3003FFFF)의 핑거 DMA 버퍼는 실리콘 하드웨어 레벨에서 캐시가 정상적으로 꺼져 있다.
- **잠재적 영향**:
  하드웨어 레벨에서 Non-cacheable로 정상 설정되어 있음에도 불구하고, `finger_bus_master.c` 수신/송신 루틴에서 `SCB_InvalidateDCache_by_Addr` 및 `SCB_CleanDCache_by_Addr`를 매 패킷마다 중복 호출한다. 이는 MPU 정책과 캐시 제어 API가 상충되는 구현으로, 불필요한 CPU 사이클 낭비 및 버스 스톨을 초래하며 캐시 일관성 정책의 혼선을 유발한다.

### 10. Cortex-M7 D-Cache 32바이트 미정렬 무효화 및 클린 루틴
- **위치**: `STM32CubeIDE/Application/User/finger_dxl/finger_bus_master.c:L855-L870, L1214`
- **위험도**: **중**
- **구조적 원인**:
  - **수신부 (RX)**:
    ```c
    SCB_InvalidateDCache_by_Addr((uint32_t *)&f_dma_rcv_buffer[finger_num][f->rcv_pre_len], len);
    ```
  - **송신부 (TX)**:
    ```c
    SCB_CleanDCache_by_Addr((uint32_t *)&t_mem_buffer[finger_num][0], len);
    ```
- **공식 기술 규격 검증**:
  ST 공식 Application Note AN4891 및 Cortex-M7 매뉴얼은 D-Cache 라인이 32바이트 단위로 관리되므로, 무효화(Invalidate) 및 클린(Clean) 대상 주소와 길이는 반드시 32바이트 경계(32-byte alignment)를 준수해야 한다고 명시한다.[^3]
- **잠재적 영향**:
  수신 오프셋(`f->rcv_pre_len`)과 전송 길이(`len`)가 32바이트 정렬을 충족하지 못한다. 비록 D2 SRAM이 Non-cacheable로 설정되어 있어 캐시 히트가 발생하지 않더라도, 비정렬 캐시 제어 API에 유효하지 않은 주소/길이를 전달하는 것은 향후 메모리 배치 변경 시 인접 데이터 손실이나 캐시 컨트롤러 오동작을 유발할 수 있는 구조적 결함 패턴이다.

### 11. D2 SRAM 상위 32KB(SRAM3) MPU 보호 영역 누락
- **위치**: `Core/Src/main.c:L1175-L1180`
- **위험도**: **중**
- **구조적 원인**:
  STM32H743VIT6의 D2 도메인 내부 SRAM은 총 288KB(SRAM1 128KB + SRAM2 128KB + SRAM3 32KB, 0x30000000 ~ 0x30047FFF)로 구성된다. 그러나 `MPU_Config`에서는 Region 1의 크기를 256KB(`MPU_REGION_SIZE_256KB`)로만 선언하여 상위 32KB인 SRAM3(0x30040000 ~ 0x30047FFF)가 MPU 명시적 보호 영역에서 누락되었다.
  *(참고: AXI SRAM 512KB 중 64KB만 선언된 것은 링커 스크립트 상 `RAM_SPI` 64KB와 일반 프로그램 메모리 `RAM_D1` 448KB의 의도된 파티셔닝이다.)*
- **공식 기술 규격 검증**:
  ST RM0433 메모리 맵 명세에 따르면, MPU 영역으로 지정되지 않은 주소는 기본(Background) 메모리 맵 규칙을 따른다.[^1]
- **잠재적 영향**:
  향후 버퍼 확장이나 다른 페리페럴 DMA 버퍼가 SRAM3(0x30040000 이후) 영역에 배치될 경우, 기본 캐시 속성(Write-Back Cacheable)이 적용되어 DMA 데이터 일관성 깨짐 현상이 발생할 수 있다.

---

### 12. Cortex-M7 비정렬 메모리 접근 트랩 강제 비활성화
- **위치**: `Core/Src/main.c:L374`
- **위험도**: **하**
- **구조적 원인**:
  ```c
  SCB->CCR &= ~(SCB_CCR_UNALIGN_TRP_Msk); // allows unaligned access
  ```
- **공식 기술 규격 검증**:
  ARMv7-M 아키텍처 및 Cortex-M7 프로그래밍 매뉴얼에 따르면, `UNALIGN_TRP` 비트를 해제하더라도 **Device Memory 및 Strongly-ordered Memory 영역에 대한 비정렬 접근은 하드웨어 예외 없이 강제 HardFault를 유발**한다.[^4]
- **잠재적 영향**:
  정렬되지 않은 포인터를 사용하는 드라이버 코드가 일반 SRAM에서 동작하더라도, 향후 MPU 속성이 Device로 지정된 주변장치 레지스터나 특정 DMA 공유 영역에 접근할 경우 즉각 하드폴트 크래시를 유발한다.

### 13. DMA 컨트롤러 Direct Mode 고정으로 인한 AHB 버스 경합
- **위치**: `Core/Src/usart.c:L428, L445`
- **위험도**: **하**
- **구조적 원인**:
  6개 채널의 UART RX/TX DMA 설정이 모두 `FIFOMODE_DISABLE` (Direct Mode)로 지정되어 있다.
- **공식 기술 규격 검증**:
  ST AN4031에 따르면 Direct Mode는 매 바이트마다 버스 요청을 발생시키며, 고속 멀티채널 환경에서는 버스 점유율을 가중시킨다.[^9]
- **잠재적 영향**:
  6개 채널이 동시에 4 Mbps로 통신할 때 D2 도메인 AHB 버스 매트릭스에 개별 싱글 트랜잭션이 누적되어 버스 대역폭 효율을 떨어뜨린다.

### 14. I2C4 BDMA 버퍼 메모리 도메인 제약
- **위치**: `Core/Src/i2c.c:L94`
- **위험도**: **하**
- **구조적 원인**:
  I2C4의 수신 DMA로 `BDMA_Channel0` (D3 도메인)을 사용한다.
- **공식 기술 규격 검증**:
  ST RM0433 버스 아키텍처에 따르면, BDMA는 물리 버스 연결 구조상 D3 도메인의 SRAM4(0x38000000) 및 백업 SRAM에만 접근할 수 있다.[^10]
- **잠재적 영향**:
  만약 I2C 수신 버퍼가 D1 SRAM(0x24000000)이나 D2 SRAM(0x30000000)에 할당되면 하드웨어 버스 에러가 발생한다. 링커 스크립트의 `.bdma_buf` 섹션 배치가 필수적이다.
